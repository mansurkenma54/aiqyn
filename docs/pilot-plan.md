# AIQYN ZHOL — пилот жоспары

Мақсат: хакатон демосынан Шымкенттегі шынайы пилотқа өту.
**Мақсат сандары алдын ала жазылмайды** — бұл құжат қандай метрика
өлшенетінін бекітеді, ал нәтиже пилоттан кейін айтылады.

---

## 1-кезең · Орнату және калибрлеу (1–2 апта)

**Ауқымы:** 1–2 қызметтік/патруль көлігі.

| Не | Неге маңызды |
|---|---|
| Камераны әйнекке ~1,2–1,5 м биіктікке бекіту | Модель dashcam ракурсында үйретілген |
| 15–20° төмен қарату, кадрдың 60%+ жол болуы | Ракурс дұрыс болмаса дәлдік құлайды |
| Қуат көзін дабыл шамынан алу | Жүргізушіге жаңа әрекет қосылмауы керек |
| GPS дәлдігін тексеру | Далалық тестте ±6 м алынды |
| **Ағын кідірісін өлшеу** (`stream_latency_sec`) | 60 км/сағ = 17 м/сек. Кідіріс дұрыс өлшенбесе, маркер жолдан жылжиды |
| Маршрутты белгілеу | Қай көшелер қамтылатыны алдын ала белгілі болуы керек |

**Шығу критерийі:** бір рейс толық өтіп, кемінде 10 оқиға дұрыс
координатамен порталға түсті.

---

## 2-кезең · Көлеңке режимі — shadow mode (2–4 апта)

Ең маңызды кезең. Мұнда жүйе **ресми өтінім жібермейді.**

| Не болады | Не жиналады |
|---|---|
| AI ақауды табады, оқиға құрады | Детекция журналы |
| Оператор әрқайсысын растайды немесе қабылдамайды | **Жергілікті ground truth** |
| Қабылдамау себебі таңдалады | Жалған детекцияның түрлері |
| Сенімділік шегі нақтыланады | Шымкент жолдарына сай `conf_threshold` |

Осы кезеңнің соңында ғана «біздің дәлдігіміз мынадай» деп айтуға болады.
Оған дейін — айтылмайды.

**Шығу критерийі:** кемінде 300 расталған/қабылданбаған шешім жиналды.

---

## 3-кезең · KPI өлшеу (1 апта)

Өлшенетін метрикалар (мақсат сандары емес — атаулары):

| Метрика | Не көрсетеді |
|---|---|
| Оператордың растау үлесі | Модель операторға пайдалы ма |
| Жалған детекция үлесі | Шек дұрыс қойылған ба |
| Қайталану (дубликат) үлесі | Дедупликация жеткілікті ме |
| Детекциядан кезекке дейінгі уақыт | Тізбек жылдамдығы (қазір: медиана 15,0 сек) |
| GPS түзету жиілігі | Координата дәлдігі жеткілікті ме |
| Маршрут қамтуы | Қанша көше қамтылды |
| Синхрондау сәтсіздігі | Байланыс сенімділігі |
| Оператордың санатты өзгерту жиілігі | Классификация дұрыстығы |

**Шығу критерийі:** сандар кестеге түсті, әкімдікке көрсетуге дайын.

---

## 4-кезең · Интеграция (келісім бойынша)

Тек расталған оқиға беріледі.

```
AIQYN оқиғасы
     ↓
Оператор растады
     ↓
Интеграция adapter
     ├── ЕКЦ 109 өтінімі
     ├── SDR оқиға тіркеуі
     ├── ЦС ГГ НИПД кеңістіктік байланыс
     └── Жол қызметінің жұмыс ағыны
```

Осы кезеңде міндетті түрде қосылады:

- сервер жағындағы сессиялар, SSO;
- рөлдер: оператор · жетекші · жол қызметі · әкімші · тек оқитын менеджер;
- аудит журналы (кім, қашан, нені растады);
- медианы сақтау мерзімі және өшіру саясаты;
- шифрланған тасымал, кілттерді қауіпсіз сақтау;
- резервтік көшірме.

**Шығу критерийі:** бір расталған оқиға нақты қалалық жүйеде тіркелді.

---

## 5-кезең · Ауқымдау (пилоттан кейін)

1. Бір аудан — 5–10 көлік
2. Қала — қызметтік автопарк
3. Басқа қалалар

Әр жаңа көлік — жаңа маршрут емес, бар қозғалысқа қосылған тағы бір көз.
Сондықтан қамту сызықты өспейді, ол автопарк өлшеміне қарай өседі.

---

## Тәуекелдер және оларға жауап

| Тәуекел | Жауап |
|---|---|
| Жергілікті дәлдік күтілгеннен төмен | Shadow mode дәл осы үшін бар. Шек нақтыланады, қажет болса жергілікті деректе қайта үйрету |
| Оператор жүктемесі артады | Дедупликация + сүзгілер + басымдық. KPI-да «оператордың бір оқиғаға кететін уақыты» бақыланады |
| Жаңбыр/қар/қарсы жарық | Пилот кезеңі әр түрлі ауа райын қамтуы керек. Нәтиже model-card-қа жазылады |
| Камера жабдығының тозуы | Жинақ ауыстырылатын болуы керек, шығын моделіне кіреді |
| Құпиялық сұрақтары | `docs/data-privacy.md` — жүйе тұлғаны да, нөмірді де танымайды |
| Ресми API ашылмауы | Экспорт (DOCX/CSV/JSON) арқылы жұмыс жалғасады, интеграция кейін қосылады |

## Бизнес моделі

**B2G:** муниципалдық бақылау бағдарламасы + орнату/қызмет көрсету.

Кіріс құрамдастары:

- жылдық бағдарламалық лицензия;
- камера/edge жинағын орнату;
- калибрлеу және операторларды оқыту;
- модель жаңартулары;
- техникалық қолдау;
- интеграция/экспорт adapter;
- аналитика модулі.

**Баға пилотқа дейін айтылмайды.** Реті: алдымен пилот KPI дәлелденеді,
содан кейін жабдық саны, интеграция көлемі және автопарк өлшеміне қарай
келісімшарт моделі құрылады.
